# 01 需求

## 用户

短视频创作者 / 品牌内容运营。需要一份能直接改、能拿去拍、每句产品描述都有出处的分镜脚本。

## 目标

| 输出字段 | 含义 |
|---|---|
| `title` | 标题 |
| `shots` | 分镜：画面、旁白/字幕、引用素材 ID、该镜估算秒数 |
| `total_seconds` / `target_seconds` | 估算总时长与目标时长 |
| `sources` | 引用的素材与其事实 |
| `risks` | 风险（违规项、时长偏短等） |
| `checks` | 终稿是否经过估算、是否通过规则检查、脚本哈希 |
| `task_status` | completed / needs_input / no_material / duration_not_met / rule_not_met / failed / unverified / incomplete |

## 输入

```json
{"topic": "快剪 App 自动字幕", "audience": "vlog 新手", "platform": "抖音",
 "target_duration_sec": 30, "style": "轻松"}
```

`topic`、`platform`、`target_duration_sec` 为关键信息。材料：`data/materials.json`（P01 快剪 App，只有“支持字幕”一条事实；P02 X1 运动相机；P03 支架）、`data/brand_rules.json`（B01–B05 与时长估算参数）。

## 范围

做：素材检索与改写、基于素材写分镜、时长估算与压缩、规则检查与修改、缺信息/无素材/工具失败/超时的明确状态。

不做：真实视频生成、配音、多平台差异化排版、界面。

## 成功标准

1. 五个必须验收点（正常生成、缺关键信息、无素材、工具失败、超时长后的修正或明确失败）各有用例且检查全部通过。
2. 关键缺陷为零：
   - 不编造产品事实：旁白中的数字都出现在所引素材的事实里，不出现“效率提升 80%”；
   - 每个涉及事实的分镜都标注素材 ID，且 ID 存在；
   - 标为 completed 的终稿必须正是通过时长估算和规则检查的那一版，总时长取估算值。
3. 参考实例：P01、30 秒，首稿 38 秒 → 压缩后重新估算并在 30 秒内，输出含分镜、P01 引用、总时长。
4. 达到步数或调用上限时返回 `incomplete`，不输出未经检查的终稿。
5. 至少两条执行路径体现动作随工具结果改变：同一素材目标 30 秒需要压缩（c05）vs 45 秒不需要（c10）；规则检查通过直接提交（c01）vs 不通过先修改（c07）。

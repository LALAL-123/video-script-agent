# 05 复盘

> 初稿，按本人实际体会修改。

## 最难的问题

**怎么证明“交出去的就是检查过的那一版”。** 模型可能在检查通过后又顺手改几个字再提交，也可能直接把首稿交上来并写一个好看的总时长。做法是让估算与检查工具都返回 `script_hash`，护栏在 finish 时重算终稿哈希并查找对应记录：没估算、超时、没检查、检查未通过，都不能是 completed；总时长取估算值，不取模型自报值。

**“不编造事实”如何机械检查。** 完全的语义核查做不到，但最危险的编造（效果数据、参数）几乎都带数字。规则 B02 要求旁白里的每个数字都出现在该分镜引用素材的事实里，“效率提升 80%”在 P01 下必然违规；型号（X1）通过正则排除，避免误报。验收检查再独立地用素材原文复核一遍。

**参考实例的可复现。** 时长估算采用固定口径（每 4.5 字 1 秒 + 每镜 1 秒），评审可以手算；用例中首稿 38 秒、压缩后 29 秒都能逐镜核对。

## 学习收获

- 修正循环的关键是工具返回“差多少”（`over_by_seconds`、违规条目），而不只是“过/不过”。
- 对照用例最能说明决策：同一素材只改目标时长（c05 vs c10），看是否触发压缩。
- 让写作结果作为工具参数流转，每一版脚本都留在 Trace 中，修正过程可审计。
- 事后降级能保证不虚报，但换不来完成率：第 2 轮护栏 17 次把 completed 降级，检查通过率仍只有 20/41。要让模型走完闭环，应在 finish 时退回而不是只降级。

## 下一步

1. GLM-4-Flash 第 2 轮常跳过估算与检查直接 finish。下一步让护栏在终稿未经估算/检查时退回模型而不是只降级，并把估算与检查合并为一个工具；再换更强的模型对比压缩轮数与护栏校正次数。
2. 时长估算区分口播与纯画面镜头，并支持平台语速差异。
3. 给素材事实加粒度（功能/参数/适用条件），把 B02 从“数字出处”扩展到“功能出处”。
4. 增加创作者反馈轮：用户修改某镜后只重估该镜并重查。
